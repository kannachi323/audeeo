# Automatic stop on silence

By default the relay ends a session after 30 continuous seconds without input at or above −60 dBFS. Audio & Languages in the caption panel lets users choose 10–300 seconds and −80 to −30 dBFS before starting. Preferences persist locally and travel with each session; the relay bounds untrusted values and defaults missing or invalid values. It measures 16 kHz PCM16 input in 20 ms RMS windows before provider resampling, independently of source/translation playback volume, provider turn detection, caption events, and generated audio. This is a digital signal threshold, not a microphone-calibrated acoustic decibel measurement. Quiet background noise above the threshold can keep a session active.

The guard starts when the provider is ready. Missing packets and zero-length packets cannot keep a session alive. A dedicated 250 ms relay watchdog runs independently of asynchronous usage reservations and client UI timers; audio arriving after the deadline cannot revive the session. Normal speech or other source sound resets the deadline. Settings are shared through `shared/silence.ts`; an active session keeps its initial settings.

On timeout the relay immediately closes the provider socket, cancels timers and further usage reservations, flushes received caption text, and sends `finished` with reason `silence timeout`. It does not create a conversational turn, wait for another provider response, or automatically reconnect. Captured audio stops through the existing client finish handler; source playback was never changed by the desktop input mixer, and already queued translation playback can drain. The app explains the stop and offers its normal Start action. Closing immediately means a provider correction or generated audio not yet delivered can be lost. Existing 15-second allowance reservations are unchanged; this does not refund already reserved usage or claim exact provider savings.

Automated verification: threshold/noise, brief sounds, view offsets, 60 seconds of active streaming, 30 seconds of silence in both modes, missing packets, activity resetting the deadline, output audio not resetting it, both sockets closing, no late audio forwarding, and timer cleanup. `npm run check`: 79 tests passed, frontend build and relay typecheck passed. These are simulated sockets/timers, not live OpenAI or physical audio tests.

Rollout requires deploying the updated relay and reopening the rebuilt desktop app for the explanatory message. Building the app alone does not deploy the relay. No deployment or live cost measurement was performed for this change.

The app opens directly to the caption panel, even while signed out. Start opens Account within the same window if authentication is required; once authenticated, Start retains the caption panel and activates overlay window behavior when listening begins. Stop returns that panel to normal window behavior after playback drains. Automated UI tests verify the same caption element survives Start/Stop and preferences persist across remounts.
