# OpenAI streaming and audio

Subtitles use `gpt-live-transcribe` over `/v1/realtime?intent=transcription`, with 24 kHz PCM16 input, `languages: [source]`, `delay: low`, and `turn_detection: null`. Audio is appended continuously. There are no periodic commits, client pause detectors, or model substitutions. Transcript deltas display immediately; stopping capture sends the sole `input_audio_buffer.commit` and waits for the matching final item.

The [official transcription guide](https://developers.openai.com/api/docs/guides/realtime-transcription) suggests automatic VAD generally, but live tests on September 13, 2026 rejected both `server_vad` and `semantic_vad` with `Turn detection is not supported for this transcription model.` The null configuration was accepted and emitted deltas before commit. This is a verified model limitation, not evidence that transcription must wait for a final turn. Long sessions approaching model/server limits still require qualification; no custom segmentation is silently added.

Translation uses `gpt-realtime-translate` over `/v1/realtime/translations`, with `audio.output.language`. It sends `session.input_audio_buffer.append`, including silence, and forwards `session.output_transcript.delta` and `session.output_audio.delta`. It sends `session.close` on stop and continues receiving until `session.closed`. No conversation turns or `response.create` are used. See the [translation guide](https://developers.openai.com/api/docs/guides/realtime-translation) and [audio event schema](https://developers.openai.com/api/reference/resources/realtime/translation-server-events#session-output-audio-delta).

Live audio events reported PCM16, 24 kHz, mono. The relay checks format metadata and forwards that PCM. Native playback provides an independent gain/mute, generation-safe completion callbacks, and a maximum 60-second translated-audio queue; exceeding the bound stops playback and the session with an error. Output may arrive faster than it plays. The window remains in overlay mode while the remaining audio drains. Stopping again during playback-only activity discards that tail. Browser playback uses the same sample format and bound; iOS receives PCM in its native session. Physical browser/iOS speech playback has not been qualified.

On macOS 14.2+, a private Core Audio global process tap excludes Audeeo's process. All Mac playback runs in that excluded native process. `mutedWhenTapped` suppresses direct source output only while the private aggregate device reads it; Audeeo monitors the tap through a separate gain/mute. The source gain does not change the bytes sent to OpenAI. Capture is converted from the tap format to 24 kHz mono, then continuously resampled to the relay's existing 16 kHz input contract. Monitoring has a one-second bound and a bounded callback queue. Stop, initialization failure, queue errors, and default output device changes release the reader, aggregate device, and tap. No system/device volume setting is changed. See Apple's [tap mute behavior](https://developer.apple.com/documentation/coreaudio/catapmutebehavior). Earlier macOS versions show a capability error when starting system audio; microphone captions remain available. Microphone speech playback should use headphones to avoid acoustic feedback.

Caption pagination is entirely local and uses actual browser line layout, including CJK wrapping and font fallback. One language gets two lines; bilingual captions get one line each. Resizing and font changes recalculate the most recent suffix. History receives full segments, not display suffixes. Translation text is grouped into history records at punctuation/300 characters without affecting provider audio or lifecycle. On disconnect, received unfinished transcription text is preserved as a snapshot; it may lack provider final corrections.

The root `.env` supplies the server-only `OPENAI_API_KEY`; provider keys never enter the frontend. Authentication, `DEV_USER_IDS`, billing reconciliation, allowance reservation, expiry, and rate checks retain their existing behavior. No unused provider was added or activated.

Run `node scripts/check-openai-live.mjs <24kHz-mono-PCM16-file>` to repeat configuration, streaming, audio-format, and close/drain tests with synthetic audio. The report is written to `artifacts/openai-streaming-verification.json` without audio, transcript, or credentials. Live OpenAI use remains billable.

## Language controls (2026-09-13)

Source and translation target are independent. Translation exposes all 13 output languages and the 74 named input languages from the [OpenAI translation cookbook](https://developers.openai.com/cookbook/examples/voice_solutions/realtime_translation_guide#supported-languages). Translation detects the actual input from audio; the selected source is session metadata, not a forced recognition parameter. Auto-detect is available in both modes. Transcription auto-detect omits `languages` entirely; an empty array is rejected.

The transcription guide documents code formats but no exhaustive language matrix. `shared/languages.ts` uses codes accepted by live `gpt-live-transcribe` session updates, verified without sending audio. We tested all ISO 639-1 codes plus the documented Cantonese, Mandarin, and regional Chinese hints; see `artifacts/language-validation.json`. Accepted configuration is not an audio-quality evaluation. ISO 639-3 aliases are not duplicated for every language. The generic unsupported-code error lists fewer languages than the model actually accepts, so that error text is not used as the catalog.

The relay validates source and target against the same catalogs as the UI. Unsupported translation targets are rejected before metering. When switching modes with an incompatible source hint, the source resets to Auto-detect. The history migration `20260913185000_caption_languages.sql` replaces the original English/Chinese constraints with bounded language-code validation while preserving grants, ownership policies, and existing records. Deploy this migration and the updated relay with the client.

Dropdowns use Radix Select, following Misty's dark surfaces, subtle borders, hover rows, and selection checkmarks. Both the control popover and its menu open downward; the macOS window expands to 640px while a popover is open, keeping the 248px caption panel in place. Escape closes the select first, then the parent popover and restores trigger focus.
